# Nextcloud Notifications Service

The Nextcloud Notifications service is a background event listener that polls the Nextcloud Notifications API and Activity API, classifies events by type, and routes them to the agent. This enables Hermes to react to Deck card assignments, file shares, calendar invitations, and other Nextcloud events.

## Prerequisites

- A Nextcloud instance with the Notifications and Activity apps enabled (included by default)
- A Nextcloud user account for Hermes (the same user used for the Talk adapter works)
- At least one messaging platform configured (e.g., Nextcloud Talk) for event delivery

## How It Works

1. The service polls both the Notifications API (ETag-optimized) and the Activity API every 30 seconds
2. Each event is matched against configurable rules (app, object_type, type)
3. **React** events trigger a full agent session — Hermes sees the event and takes action
4. **Silent** events are stored persistently for later retrieval
5. Events generated by Hermes itself are automatically filtered to prevent loops
6. Processed notifications are marked as read

The Activity API is polled alongside the Notifications API because some Nextcloud events (e.g., files added to shared folders) only appear as activities, not as notifications.

## Configuration

Add a `services` section to your `~/.hermes/config.yaml`:

```yaml
services:
  nextcloud_notifications:
    enabled: true
    extra:
      poll_interval: 30                          # seconds between polls
      deliver: nextcloud_talk:your_conv_token     # where to send react events
      rules:
        - app: deck
          object_type: deck_card
          type: deck_card_description
          action: silent                         # ignore description edits
        - app: deck
          object_type: deck_card
          action: react                          # card assignments → agent session
        - app: files_sharing
          object_type: files
          type: shared
          action: react                          # file shares → agent session
        - app: files
          object_type: files
          type: file_created
          action: react                          # new files in shared folders
        - app: dav
          object_type: calendar_event
          action: react                          # calendar invitations
        - app: "*"
          action: silent                         # everything else → store silently
```

### Credential Sharing

If `nextcloud_url`, `username`, or `app_password_env` are not specified in the service config, they are automatically inherited from the `nextcloud_talk` platform configuration.

### Rules

Rules are evaluated top-to-bottom, first match wins. Each rule can match on:

| Field | Description | Example |
|-------|-------------|---------|
| `app` | The Nextcloud app that generated the event | `deck`, `files_sharing`, `files`, `dav` |
| `object_type` | Object classification (Activity API value) | `deck_card`, `files`, `calendar_event` |
| `type` | Activity subtype for fine-grained filtering | `shared`, `file_created`, `deck_card_description` |
| `action` | What to do: `react` or `silent` | `react` |

Use `"*"` as a wildcard to match any app. If no rule matches, the event is treated as `silent`.

**Important:** The Activity API uses different field values than the Notifications API. For example, a file share has `object_type=files` and `type=shared` in the Activity API, but `object_type=shared` in the Notifications API. Always use Activity API values in your rules, as that is the primary event source.

### Delivery Target

The `deliver` field specifies where react events are sent: `platform:chat_id` (e.g., `nextcloud_talk:abc123xy`).

## Supported Event Types

| App | object_type | type | Description | Recommended |
|-----|-------------|------|-------------|-------------|
| `deck` | `deck_card` | `deck` | Card assigned/moved | `react` |
| `deck` | `deck_card` | `deck_card_description` | Card description edited | `silent` |
| `files_sharing` | `files` | `shared` | File shared with Hermes | `react` |
| `files` | `files` | `file_created` | File added to shared folder | `react` |
| `dav` | `calendar_event` | — | Calendar invitation | `react` |

## Architecture: Services

The Notifications service introduces a **Services** concept in the gateway, distinct from **Platforms** (chat channels):

- **Platforms** are bidirectional chat channels (Talk, Email, Telegram)
- **Services** are background event listeners that route events to platforms

Services are started after platforms and stopped before platforms during shutdown.

## Troubleshooting

### Service doesn't start

- Check that `NEXTCLOUD_TALK_APP_PASSWORD` is set in `~/.hermes/.env`
- Verify the Nextcloud URL is reachable from the gateway
- Check gateway logs: `journalctl -u hermes-gateway`

### No reaction to events

- Verify rules match the Activity API field values (use `object_type=deck_card`, not `object_type=card`)
- Check that events appear in the Activity API: `curl -u hermes:$PW https://nc.example.com/ocs/v2.php/apps/activity/api/v2/activity`
- Note: The Activity API has server-side caching — events may take 1-2 minutes to appear

### Events from Hermes itself

Events generated by the `hermes` user are automatically filtered out. This prevents notification loops when Hermes creates files, modifies Deck cards, etc.
